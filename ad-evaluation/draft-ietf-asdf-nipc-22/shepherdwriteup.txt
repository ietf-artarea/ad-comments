&gt;Describe the document shepherd's review of the IANA considerations section,
&gt;especially with regard to its consistency with the body of the document.
&gt;Confirm that all aspects of the document requiring IANA assignments are
&gt;associated with the appropriate reservations in IANA registries. Confirm
&gt;that any referenced IANA registries have been clearly identified. Confirm
&gt;that each newly created IANA registry specifies its initial contents,
&gt;allocations procedures, and a reasonable name (see <a href="/doc/rfc8126/">RFC 8126</a>).

In the IANA Considerations section, the authors request:

- A "application/nipc+json" media type for NIPC APIs messages
- A new registry "NIPC API extensions" for the API extensions
- A well-known URI in the "Well-Known URIs" registry, namely, "/.well-known/nipc"
- A new registry called "NIPC Data Subscription Types"
- A new registry called "NIPC Protocols" for extending the supported protocols, e.g., Thread
- A new registry, "NIPC Problem Type", for problem types descriptions

The above requests to IANA are consistent with the document body.

The above requested registries are associated with the appropriate reservations
in IANA registries.

The above requested registries, or additions to existing IANA registries, have
been properly identified.

The above requested registries specifies their initial contents, allocation
procedure, and reasonable names.

There are a few open questions on whether requesting a registry group for NIPC
(and add the other registries to such groups), or add the above requested
registries to existing ones, such as the SDF IANA registry. Chairs, authors, and
WG have no strong opinions on this matter.
